## RE-20261109-001 — Initial source/architecture baseline (DOCUMENTATION BOOTSTRAP)

- **Objective:** Establish durable evidence locations and a reproducible map of original SWF → generated assets → Rust runtime; not to rewrite the game.
- **Prior problem:** Technical discoveries existed across `AI_WORKLOG.md`, old PRs, manifests and one detailed revival log, but had no dedicated research index cross-linked with a Rust compliance audit.
- **Original subsystem and source:** Flash root story on frame 18, original Level1A on root frame 19; source hashes in SRC-001; extracted action routing in SRC-002. SOURCE CONFIDENCE **MEDIUM** for the exact hashes because only their recorded manifest was read now; **HIGH** that the manifest contains these values.
- **Native subsystem:** `src/main.rs` dispatches `--render-smoke`, `--render-smoke-hq`, `--benchmark-render`, `--benchmark-scenery-scroll` and normal `win32::run`. `src/game.rs` owns the fixed-step state machine. `src/render.rs` composes source sprites into 600×400 or 1800×1200 targets. `src/win32.rs` handles Win32 input, window and DPI. `src/assets.rs` uses `include_bytes!` for generated assets. `src/audio.rs` calls WinMM/MCI to play original embedded MP3s. `src/collision.rs` decodes a generated mask.
- **Recorded measurements (direct project code):** 25 simulation steps/second (40ms each); `src/assets.rs` documents 180 story samples; source sprite #34 fadeout 41 frames (indexed 0..40); `bake_root_intro.py` checks sprite #122 length 165 frames with final Stop at index 164, and sprite #35 length 15 frames with final Stop at index 14. Source placement `(301,205)` is used for fadeout in the Rust compositor. These are code/assertion-level facts, not independently timed in a Flash player here.
- **Decision:** Keep the existing Rust runtime and offline Python asset pipeline separate. Build initial ledger and audit with exact paths, preserve existing long-form [presentation fidelity log](revival/LEVEL1A_PRESENTATION_FIDELITY_LOG_2026-11-09.md), and explicitly defer unresolved verification.
- **Alternatives:** (a) rewrite extraction tooling in Rust now (scope expansion with no evidence of runtime impurity), (b) retain offline tooling but forbid runtime script/Flash dependency. **Choose (b)** for this documentation-only batch: avoids unrelated rewrite while honoring pure-Rust playable-game rule. A future approved build-tool rewrite remains possible.
- **Tests performed in this bootstrap:** Remote GitHub head, PR, manifests, Rust source, Cargo manifest and Actions outcomes inspected. **Not run:** local `cargo test`, `cargo tree`, `cargo fmt`, visual playback or source SWF hash regeneration.
- **Uncertainties / confidence:** Transitive PNG dependency graph and compiled binary import table not checked (**UNKNOWN**); manual audio/fade visual parity (**UNKNOWN**); baseline code ownership and source provenance caveats require `THIRD_PARTY_NOTICE.md`. Cross-link [AUD-20261109-001](RUST_PURITY_AND_ENGINEERING_AUDIT.md#aud-20261109-001--baseline-rust-runtime-and-dependencies).

## RE-20261109-002 — Intro visual repetition, routing and source fade (HISTORICAL EVIDENCE RECONSTRUCTION)

**Status:** Retrospective synthesis of surviving code/manifests/worklog, not a newly performed Flash experiment. **Subsystem:** Flash root frame18, child sprites #122/#123/#126/#35, SKIP button #129 and fadeout movie #34. **Rust modules:** `src/game.rs`, `src/render.rs`, `src/win32.rs`, `src/headless.rs`, offline `reverse-engineering/tools/inspect_intro_behavior.py` and `bake_root_intro.py`.

**Initial question.** Why did the story show nearly-black flashes at repeated short intervals, end too early, and instantly jump on SKIP? The previous renderer baked recursively sampled sprites using generic modulo-frame timelines. The previous game state also jumped to gameplay after 180 samples.

**Recorded original-source findings and their origins:**
1. Worklog's [diagnostic Run #42582404902](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42582404902) generated 180 frame metrics and reported dark frames 15,30,45,... (0-based) every 15/25 = **0.6 s**. Its report measures the *baked native output*, not original Flash on-screen truth.
2. Source sprite **#35** contains terminal `Stop` at frame **14** (0-based), `DefineSprite` payload-relative action byte **207**, according to prior [Run #42583921359](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42583921359) source-action report and surviving log. Source sprite **#122** contains terminal `Stop` at frame **164**, payload-relative byte **47244**, with 165 source frames. Generic `frame % len` can restart a stopped sprite; intro baker explicitly holds both.
3. Previous [Run #42587338561](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42587338561) was green after sprite35 correction; worklog records near-black fractions ~0.609 at frames 15/30/45/60 rather than 1.000. **Confidence HIGH** in documented diagnostic pattern, **MEDIUM** in precise historical comparisons pending artifact re-download.
4. Source button **#129**, DefineButton2 SWF tag byte **376676**, conditional action byte **376745**, has event mask **0x0800** (mouse release inside); it sets `_root.gotoNext = "level1a"` and calls `_root.fadeout.play()`. Earlier decoding treated the SWF bitfield as little-endian and mislabeled an End-key event, later corrected. Nested sprite **#123** frame179 Stop/StopSounds and fadeout sprite **#34** frame39 StopSounds / frame40 dispatcher are captured in source-audit/worklog. Verify offsets against generated report if moving tooling.
5. Current Rust at `c2b872e`: `Game::skip_intro` arms `intro_fadeout_tick`; `Game::tick` advances source 0..40 at 25 Hz and starts Level1A after frame40. Native Win32 mouse tracks press-inside/release-inside; renderer overlays source fade pack (legacy 1×, HQ 3×). The story remains at frame179 until explicit interaction.

**Candidate explanations compared:** (A) original deliberately flashes black every 15 frames; (B) a stopped child is erroneously looped by the native asset baker; (C) invalid alpha/transform blending; (D) duplicate fade overlay. The exact 15-frame recurrence and source sprite35 terminal Stop support **B**. That evidence does not exclude other compositor problems; root-frame comparisons are still needed. For the early cutoff, source stopped root timeline plus release-handler fade route contradict a hardcoded immediate 180-tick jump. The full source event chain is a stronger explanation than simply choosing a longer story duration.

**Decision trace (summary of reproducible evidence, not private reasoning):** Preserve source fade frames rather than replacing with generic black tween, bake stopped clips only where AVM1 Stop was verified, place fade #34 at the source location, trigger from native release-inside semantics, and keep time advancement in Rust. Alternatives—arbitrary 7.2-to-N-second extension; skipping entire fade; embedding a Flash interpreter—would be less defensible or violate the runtime objective.

**Validation limits:** Earlier green Run #42587338561 proves that specific native diagnostic/check contract. At `c2b872e`, full CI failed (see RE-20261109-003). No recorded final side-by-side manual acceptance of cutscene timing, fonts, and sound. Confidence **HIGH** that source action data contains the routing described in surviving artifacts; **MEDIUM** for full visual/interaction fidelity.

**Follow-up:** Re-download source button and fade artifacts, capture 0/14/15/38/39/40 frames and original Flash playback; validate source event timing and audio on user Windows system. Audit linked: [AUD-20261109-001](RUST_PURITY_AND_ENGINEERING_AUDIT.md#aud-20261109-001--baseline-rust-runtime-and-dependencies).

## RE-20261109-003 — Two successive Windows render-benchmark failures (NEW CROSS-CHECK)

- **Batch/date:** BOOTSTRAP-DOCS-20261109; repo commit `c2b872e` (baseline), earlier `da30511`; CI-002 and CI-003. Confidence **HIGH** in failure and source-level contradiction; **MEDIUM** that the contradiction uniquely explains the OS exit status.
- **Question:** Why do both Windows workflows fail at the benchmark despite green unit compilation?
- **Observed:** [#42589238951](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42589238951) and [#42591045102](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42591045102) both compile release Rust and report **9 unit tests passing**; both fail at job `windows-x64`, step **22**. The PowerShell command launches `--benchmark-render 60 .generated/render-benchmark.json`, which exits **-1073740791 (hex 0xC0000409)**. This is a process exit status, not itself a full stack trace.
- **Directly identified test-code inconsistency:** At `c2b872e`, `src/headless.rs::benchmark_render` starts the title, sends Enter, then executes `for _ in 0..180 { game.tick(...) }` and `assert_eq!(game.screen, AppScreen::Playing)`. But `src/game.rs::tick` **deliberately holds `AppScreen::Intro` at `intro_tick=179` until explicit SKIP**. No SKIP is sent in that benchmark. Therefore that assertion cannot pass for the intended current behavior. The release Cargo profile specifies `panic = "abort"`, consistent with a process termination rather than a printable unwind. This code contradiction is **HIGH confidence**; confirming the precise Windows failure mechanism still requires a targeted debug run.
- **Rejected/less supported hypotheses:** A generic unrenderable sprite does not explain the obvious unreachable Playing state. A Win32 native crash, memory error, or decoding fault is **not ruled out** solely by the exit code and should be investigated if the explicit-SKIP test fix does not resolve it. No crash dump has been inspected.
- **Recommended SINGLE next code batch (not implemented here):** Make `benchmark_render` request `skip_intro()`, advance all 41 fade frames, assert `Playing` with source-correct timing, then run `cargo test`, release build, `--benchmark-render 60`, both smoke modes and full Windows CI. Do not weaken the benchmark or disable the assertion; make it follow the real game state machine. Test on the pinned CI-generated asset set.
- **Reproduction:** GitHub workflow `.github/workflows/build-level1a-fidelity.yml` step22; generated assets required; `cargo run --release -- --benchmark-render 60 .generated/render-benchmark.json` after complete Windows asset bake. The command is a proposed reproduction—not executed locally in this documentation batch. Refer to [AUD-20261109-001](RUST_PURITY_AND_ENGINEERING_AUDIT.md#aud-20261109-001--baseline-rust-runtime-and-dependencies).
- **Revision condition:** If benchmark still crashes after proper SKIP/fade advance, inspect Rust/Win32 crash information and `src/headless.rs` render caches rather than presuming this is the only defect.
