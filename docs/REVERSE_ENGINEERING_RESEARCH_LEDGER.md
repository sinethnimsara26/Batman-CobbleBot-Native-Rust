## RE-20261109-002 — Intro visual repetition, routing and source fade (HISTORICAL EVIDENCE RECONSTRUCTION)

**Status:** Retrospective synthesis of surviving code/manifests/worklog, not a newly performed Flash experiment. **Subsystem:** Flash root frame18, child sprites #122/#123/#126/#35, SKIP button #129 and fadeout movie #34. **Rust modules:** `src/game.rs`, `src/render.rs`, `src/win32.rs`, `src/headless.rs`, offline `reverse-engineering/tools/inspect_intro_behavior.py` and `bake_root_intro.py`.

**Initial question.** Why did the story show nearly-black flashes at repeated short intervals, end too early, and instantly jump on SKIP? The previous renderer baked recursively sampled sprites using generic modulo-frame timelines. The previous game state also jumped to gameplay after 180 samples.

**Recorded original-source findings and their origins:**
1. Worklog's [diagnostic Run #42582404902](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42582404902) generated 180 frame metrics and reported dark frames 15,30,45,... (0-based) every 15/25 = **0.6 s**. Its report measures the *baked native output*, not original Flash on-screen truth.
2. Source sprite **#35** contains terminal `Stop` at frame **14** (0-based), `DefineSprite` payload-relative action byte **207**, according to prior [Run #42583921359](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42583921359) source-action report and surviving log. Source sprite **#122** contains terminal `Stop` at frame **164**, payload-relative byte **47244**, with 165 source frames. Generic `frame % len` can restart a stopped sprite; intro baker explicitly holds both.
3. Previous [Run #42587338561](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42587338561) was green after sprite35 correction; worklog records near-black fractions ~0.609 at frames 15/30/45/60 rather than 1.000. **Confidence HIGH** in documented diagnostic pattern, **MEDIUM** in precise historical comparisons pending artifact re-download.
4. Source button **#129**, DefineButton2 SWF tag byte **376676**, conditional action byte **376745**, has event mask **0x0800** (mouse release inside); it sets `_root.gotoNext = "level1a"` and calls `_root.fadeout.play()`. Earlier decoding treated the SWF bitfield as little-endian and mislabeled an End-key event, later corrected. Nested sprite **#123** frame179 Stop/StopSounds and fadeout sprite **#34** frame39 StopSounds / frame40 dispatcher are captured in source-audit/worklog. Verify offsets against generated report if moving tooling.
5. Current Rust at `c2b872e`: `Game::skip_intro` arms `intro_fadeout_tick`; `Game::tick` advances source 0..40 at 25 Hz and starts Level1A after frame40. Native Win32 mouse tracks press-inside/release-inside; renderer overlays source fade pack (legacy 1×, HQ 3×). The story remains at frame179 until explicit interaction.

**Candidate explanations compared:** (A) original deliberately flashes black every 15 frames; (B) a stopped child is erroneously looped by the native asset baker; (C) invalid alpha/transform blending; (D) duplicate fade overlay. The exact 15-frame recurrence and source sprite35 terminal Stop support **B**. That evidence does not exclude other compositor problems; root-frame comparisons are still needed. For the early cutoff, source stopped root timeline plus release-handler fade route contradict a hardcoded immediate 180-tick jump. The full source event chain is a stronger explanation than simply choosing a longer story duration.

**Decision trace (summary of reproducible evidence, not private reasoning):** Preserve source fade frames rather than replacing with generic black tween, bake stopped clips only where AVM1 Stop was verified, place fade #34 at the source location, trigger from native release-inside semantics, and keep time advancement in Rust. Alternatives—arbitrary 7.2-to-N-second extension; skipping entire fade; embedding a Flash interpreter—would be less defensible or violate the runtime objective.

**Validation limits:** Earlier green Run #42587338561 proves that specific native diagnostic/check contract. At `c2b872e`, full CI failed (see RE-20261109-003). No recorded final side-by-side manual acceptance of cutscene timing, fonts, and sound. Confidence **HIGH** that source action data contains the routing described in surviving artifacts; **MEDIUM** for full visual/interaction fidelity.

**Follow-up:** Re-download source button and fade artifacts, capture 0/14/15/38/39/40 frames and original Flash playback; validate source event timing and audio on user Windows system. - [Windows Run #42589238951](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42589238951) at `da305119...` and [Run #42591045102](https://github.com/sinethnimsara26/Batman-CobbleBot-Native-Rust/actions/runs/42591045102) at `c2b872e...` each failed at workflow job `windows-x64`, step **22**, `Smoke-check executable, legacy pixels, HQ output and render timing`: `--benchmark-render 60` exited Windows `-1073740791` (**0xC0000409**), after successful release compilation and **9 passing Rust tests**. Earlier visual-smoke child processes were successful. There was no verified standalone `render-benchmark.json` output or useful panic backtrace from those runs. See [RE-20261109-003](#re-20261109-003--two-successive-windows-render-benchmark-failures-new-cross-check).
- **Directly inspected code contradiction:** At predecessor `4ee103a`, `src/headless.rs::benchmark_render` never called `Game::skip_intro`, but required `Playing` after 180 ticks. `src/game.rs::tick` holds `Intro` indefinitely at frame179 absent SKIP. This explains a definite failed assertion in the old benchmark path, independent of other possible crash causes.
- **Windows status limitation:** Microsoft defines `0xC0000409` as a fail-fast exception that may result from various application conditions and requires the **first exception parameter/subcode** for a more specific determination; no such record was captured here. It is **incorrect** to declare a proven stack buffer overrun. Source: *Fail Fast Exception C0000409*, Microsoft Learn / Inside Show, 2018-01-29, https://learn.microsoft.com/en-us/shows/inside/c0000409, section *Fail Fast Exception*; accessed 2026-11-09.

### Candidate explanations, contradictions and decision

1. **Stale benchmark scene-setup assertion (HIGH support):** benchmark expected the obsolete automatic 180-tick transition. Confirmed by exact old Rust code and the new `Game::tick` implementation; this must be repaired regardless of which Windows failure subcode occurred.
2. **Asset decoder, HQ compositor, or `unsafe` platform corruption (LOW current support):** possible but not established. Render smoke executed successfully and the benchmark's own immediate scene assertion is known to fail before its rendering samples. A repeat crash after the setup fix would justify testing this separately.
3. **Source intro should automatically advance at 180 (CONTRADICTED):** original root/frame Stop and action-based button route provide evidence against that shortcut; changing the playable game's source-correct behavior would be a fidelity regression.
4. **Disable/remove assertion or skip benchmark entirely (REJECTED):** would turn the test green by weakening it, not by fixing test setup. It would also conceal future routing regressions.

**Selected approach:** Change **only** `src/headless.rs::benchmark_render`: after title Enter, advance 180 ticks, assert `Intro`, index179 and no active fade; request `game.skip_intro()` (asserting success); assert fade frame0; advance **40** ticks, assert frame40 is still displayed in Intro; advance the **41st** tick, assert `Playing`, cleared fade and gameplay `ticks==0`; then resume original `while game.ticks<105` gameplay warm-up and **unchanged** HQ measurement/report code. This uses the real Rust state machine rather than manually changing `game.screen`. It neither introduces a new dependency nor modifies game logic, original SWF assets, physics, timer rate, rendering samples or measurement formulas.

**Timing calculation:** 25 fixed ticks/s → 1 tick = **0.04 s**. Source fade frames 0..40 = **41 frame samples**, 1.64 s of tick capacity from initial frame through exit check; 40 tick advances reach visible index40 (1.60 s after start), next tick invokes source-backed exit (1.64 s). Holding the initial story after its 180 ticks does not imply playback lasts exactly 7.2 seconds, because it stays stopped pending input.
